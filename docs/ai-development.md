# AI 辅助开发约定

开始改动前阅读需求文档、`docs/architecture.md`、`docs/domain-model.md`、OpenAPI 和目标领域代码。把需求写成可观察的状态变化与失败场景，定位负责的领域模块，确认数据库约束与外部副作用。修改接口时先更新 OpenAPI 并运行 `npm run api:generate`；修改持久状态时更新可升级迁移与 `docs/database-design.md`；重大取舍写 ADR。

每次变更保持模块边界：业务规则放在相应 `domains/*`，外部 HTTP/SSE 与数据库细节通过明确的接口或领域服务调用，避免跨模块直接复制规则。新增网关行为时覆盖 202/异步事件、重复事件、504 未知结果、503、重启恢复和终态中断。新增 Agent 工具时验证审计、协议输入输出、幂等及步骤恢复。错误码、日志上下文和指标应与业务状态同步更新。

完成后按影响范围运行构建、单元、集成和 E2E 验证，检查生成客户端、schema、文档是否同步。记录测试命令与结果；外部服务凭据不可提交。用户已授权本任务的代码实现和验证，常规文件修改无需重复请求确认；发布、外部写入或其他不可逆动作仍按明确授权执行。审查时重点看相邻领域是否受影响、故障后能否恢复、数据库约束是否支撑并发语义。
